RISK & ENGINE

SPREAD/LOCK

A cross-venue arbitrage desk for Kalshi × Polymarket prediction markets, running a live paper-trading engine entirely in your browser.

THE TRADE

For any binary market, a YES on one venue plus a NO on the other always resolves to exactly $1.00 per pair. If the combined ask is below $1.00 — net of Kalshi's fee curve 0.07 · p · (1−p), Polymarket fees, slippage, and book depth — the difference is locked profit regardless of outcome. The scanner computes this every second across both directions and both full order books.

WHY THIS IS A SIMULATED FEED

Real execution requires credentials that must never live in a browser: Kalshi uses RSA-signed API keys on trade-api/v2, and Polymarket requires an EIP-712 signature from a wallet private key for every CLOB order. Neither execution path is callable client-side (CORS + key exposure). So this desk runs against a stochastic two-venue simulator with realistic microstructure: 1¢ Kalshi ticks vs 0.1¢ Polymarket ticks, depth-limited ladders, and news jumps where one venue reprices instantly while the other lags for a few seconds — the same mechanics that produce real-world dislocations.

GOING LIVE (ARCHITECTURE)

  • Server process (Node): holds Kalshi API keys and the Polymarket signer; exposes your own authenticated endpoint to this UI.
  • Feeds: Kalshi WebSocket + REST trade-api/v2; Polymarket CLOB WebSocket + Gamma API for market discovery.
  • Matching: normalize event slugs/tickers to binary pairs — the same evalDir() math this desk runs, but against live ladders.
  • Risk: min-edge hysteresis, per-market caps, leg-risk timeout (kill an unfilled hedge), drawdown kill switch — all already modeled here.
